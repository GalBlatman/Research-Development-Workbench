# ADR 0007: canonical research workspaces and revision loop

Accepted implementation within owner-authorized RDW-006 scope. The approved stack, provider, rubric and persistence infrastructure remain unchanged. No new dependency or external service is selected.

Seven editable research-task areas use typed ResearchRecord fields within the existing ProjectObject union; Overview, Review and History render the same canonical project. Field origin and information/evidence state are separate from object adoption, support disposition and freshness. Source/version/anchor references remain scoped and authorized. Manual records and model proposals cannot declare documented/verified evidence. Completed studies and usefulness support are explicitly user-reported until independently inspected.

Workspace development and focused checking extend the existing provider-neutral adapter, strict schemas, source admission checks, shared run ledger and bounded local worker. Original prompts remain available; evaluation-v2 explicitly distinguishes manuscript-as-written from current clarified project and denies advance repair credit. Generated records are not sources. No live provider experiment is needed for this UI/state change; deterministic fake and mocked actual Responses transport exercise success, schema failure, incomplete checking and budget exhaustion.

Every edit/adoption/settings/source-version operation appends a project revision in the existing revision repository. Historical payloads, source versions, reviews and policy snapshots are immutable. Original suggestions and run hashes are retained after adoption/edit/rejection/superseding, with explicit user-action history. Historical JSON exports render stored judgments, never recalculate policy. Current staleness metadata is derived separately from immutable review content.

Minimum invalidation follows product specification 12.2 conservative workspace dependencies, explicit object dependencies and source-version counters. Users classify wording-only versus consequential changes; the system does not infer scientific importance from keywords. Resource-only changes affect next-action feasibility, not intrinsic assessment. Conservative groups can mark related records affected when finer scientific dependencies are unknown; study changes do not invalidate unrelated argument reviews. Nothing schedules an automatic paid rerun.

A targeted workspace check uses server-selected existing rubric dimensions and creates a separate immutable scoped review. It refreshes only that scope; it does not combine incompatible historical assessments into a new total. Full/revision evaluations remain explicit. Next actions are bounded proposed records with task, reason, unresolved judgment, input/output, workspace/dependency and possible outcomes. Adoption does not execute research.

Limitations: conservative dependency granularity, one bounded local worker, loopback/private single-user development, and no independent scientific validation of fake outputs. PostgreSQL parity remains mandatory in CI. GATE-2 is unstarted; this same-session implementation review does not substitute for that independent audit.
