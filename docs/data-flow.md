# Data flow

RDW-004: loopback React browser -> FastAPI request contracts/fixed server scope -> RDW-003 project/source services -> immutable original versions and anchored admitted ContextPacket -> replaceable fake adapter -> strict schema and exact FixtureVerifier -> RDW-002 pure rubric engine -> immutable StoredSnapshot with review summary -> server-generated presentation/Markdown/JSON -> browser. No external model/network operation occurs during fake evaluation. Backend storage/credentials never reach the adapter or ordinary export.

Generated interpretation/advice is separate from source text. Accepting representation creates a revision and preserves not-inspected evidence. Later edits create history and a historical-review indicator without rewriting assessment/snapshot. Private local originals and database reside in an explicit directory outside the repository; PostgreSQL remains canonical. The local slice has one fixed owner, no authenticated access or deployment claim. Host/origin boundaries are development safeguards.

Later real-provider tasks require bounded workflow/worker, separate processing consent, substantive verification, budgets and safe failure handling. Future deletion must cover originals, parsed text, records, indexes, context/output caches, reports and backups under an accepted retention design before pilot. Logs avoid confidential text/secrets; CI uses synthetic material only. No arbitrary fetching or model-selected files.
