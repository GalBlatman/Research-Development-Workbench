# RDW-003: source/document core and project persistence

Status: complete. Depends on completed RDW-002; governing rubric and product spec remain immutable.

Outcome: reloadable scoped projects, append-only revisions/source versions/snapshots, source-specific stable anchors, explicit text/Markdown availability, provenance references, deterministic portable records and authorized lexical retrieval. No application UI or evaluation workflow.

Allowed: backend/domain source/portable contracts, backend/persistence PostgreSQL adapter and lightweight SQLite test adapter, backend/services source/project/retrieval logic, synthetic backend tests, locked driver dependency, CI/database test configuration and related governance/safety documentation. Reuse RDW-002 Project, DocumentVersion, EvaluationSnapshot and Assessment rather than competing domain models.

Inputs: authenticated server actor scope, project records, authorized UTF-8 text/Markdown or attributed pasted originals/excerpts, immutable policy identity. Outputs: append-only scoped records, versioned location anchors and hashes, explicit unreadable/missing/external states, bounded admitted-source search and deterministic JSON record bundles. Original files remain outside structured records; generated/interpretive content belongs in ProjectObject, never SourceRecord. Adoption never verifies evidence.

Tests: create/save/reload without state loss; revision/version/snapshot immutability including database guards; stable correct-version anchors; generated source rejection; adoption/evidence separation; deterministic import/export preserving null/pending/not-applicable/provenance; owner/workspace/project isolation; admission and source-unavailability guards; content integrity; atomic import and conflict behavior; complete RDW-002 regression and publication checks. Run identical persistence contracts against SQLite locally and PostgreSQL in CI. Ruff lint/format and strict mypy include new modules.

Exclude: rubric changes, scientific heuristics, LLMs/SDKs/prompts, frontend research features, PDF/DOCX, embeddings/vector/graph stores, external discovery/fetching/APIs, Zotero, deployed services, RDW-004. Use synthetic fixtures only. Do not implement broader history dependency invalidation or pilot deletion/backup infrastructure.

Workflow: branch -> task checks -> staged/public-tree review -> commit/push -> successful CI -> owner-authorized integration -> clean synchronized main. Stop on policy ambiguity or genuine scope expansion; local PostgreSQL absence is handled by the explicitly permitted lightweight adapter and real PostgreSQL CI.
