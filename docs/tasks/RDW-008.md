- recoverable state;
- clear diagnostics;

- stable persistence;
- secure handling of unpublished research;

PRIVATE-PILOT MODE

Create a documented local private-pilot workflow.

A user should be able to:

1. install/start the application locally;
2. verify required configuration;
3. create a project;
4. add sources;
5. run fake-provider evaluation offline;
6. optionally run real-provider evaluation if credentials exist;
7. revise the project;
8. inspect staleness/history;
9. export the project/review;
10. shut down and restart;
11. recover the same state;
12. run the benchmark harness on synthetic fixtures.

Do not require private research material for automated acceptance.

Use synthetic research content in tests.

Private unpublished projects, if used manually by the owner later, must remain
outside Git and publication artifacts.

STARTUP / CONFIGURATION

Harden local startup.

Provide one documented path for:
- backend startup;
- frontend startup;
- database startup/configuration;
- fake-provider mode;
- real-provider mode;
- benchmark mode.

Fail clearly when:
- required database configuration is absent;
- schema is incompatible;
- provider credential is absent for real-provider mode;
- configured model/provider is unsupported;
- writable storage is unavailable.

Do not silently fall back from real provider to fake provider.

Provide a safe configuration/status command or equivalent diagnostic.

It must never print secrets.

PERSISTENCE / MIGRATIONS

Ensure production persistence is robust.

Verify:
- PostgreSQL remains canonical production persistence;
- migrations are versioned and repeatable;
- applying migrations twice is safe where appropriate;
- startup does not silently mutate scientific records;
- historical snapshots remain immutable;
- dependency lineage survives persistence/restart;
- benchmark histories remain immutable;
- imports do not overwrite incompatible existing records silently.

Add migration/upgrade tests for the schema states actually supported.

Do not create an elaborate migration framework if the approved architecture
already has one.

BACKUP / RESTORE

Provide a minimal supported local backup/restore path for private use.

The backup must preserve:
- projects;
- revisions;
- source records/versions;
- provenance;
- evaluations;
- reviews;
- suggestion states;
- histories;
- benchmark definitions/runs where applicable.

Restore must:
- validate format/version;
- reject incompatible/corrupt backups visibly;
- not silently merge conflicting histories.

Do not include secrets in backup files.

Test round-trip restoration with synthetic data.

RUN LIFECYCLE / CRASH SAFETY

Harden model-run lifecycle.

Explicitly represent at least:
- queued/preparing if used;
- running;
- completed;
- failed;
- timed out;
- budget exhausted;
- interrupted/uncertain where needed.

Ensure:
- failed/interrupted runs do not publish partial scientific conclusions as final;
- restart does not duplicate an already completed run;
- uncertain provider status remains uncertain;
- bounded retry rules remain intact;
- historical failed runs remain inspectable;
- repeated user action does not accidentally double-submit a run where idempotency
  should apply.

Test process interruption/restart using mocks.

CONCURRENCY / RACE CONDITIONS

Test realistic local concurrency cases.

At minimum:
- two edits based on the same prior revision;
- evaluation starts while project is edited;
- source version changes during evaluation;
- suggestion acceptance against a superseded revision;
- targeted reevaluation of a stale component while another revision appears;
- duplicate run request.

Required behavior:
- no silent lost update;
- no mutation of historical state;
- evaluations remain tied to the frozen revision/context they actually saw;
- conflicts surface clearly;
- completed results do not silently attach to the wrong current revision.

Do not build multi-user collaboration.

This is local consistency hardening only.

PROVIDER FAILURE HARDENING

Using fake/mocked provider boundaries, test:

- timeout;
- connection failure;
- rate limit;
- 5xx/provider transient failure;
- refusal;
- malformed structured response;
- valid schema with scientifically incomplete content;
- incomplete checking result;
- context too large;
- output budget exhausted;
- total run budget exhausted;
- credential missing;
- configured model unavailable.

Verify:
- bounded retries;
- clear failure state;
- no silent fallback;
- no accidental review publication;
- usage already incurred is recorded;
- subsequent safe retry is possible where allowed.

No live provider spend is required.

SECURITY / PRIVACY HARDENING

Audit local handling of unpublished research.

Verify:
- API keys never reach frontend;
- API keys never enter exports/backups/logs;
- source text is not emitted into routine logs;
- model request logging does not dump manuscript text;
- benchmark gold remains segregated;
- blind evaluator remains unable to access gold;
- publication guard still rejects private/source materials;
- path traversal / arbitrary local-file access is not available through source
  APIs;
- cross-project access remains rejected;
- imports cannot smuggle prohibited source authority states.

Use synthetic fixtures only.

LOGGING / DIAGNOSTICS

Make operational logs useful without leaking research content.

Logs should support diagnosing:
- run ID;
- project/revision ID where safe;
- provider/model;
- task type;
- state transition;
- timing;
- token/usage summary;
- error class.

Do NOT log:
- API keys;
- full prompts;
- full manuscript/source passages;
- hidden benchmark gold;
- chain-of-thought.

Ensure user-facing failures are understandable without exposing stack traces or
secrets.

PERFORMANCE / COST GUARDS

This is not an optimization project.

Measure enough to catch obvious operational problems.

Verify:
- large but supported text packets do not cause pathological local behavior;
- targeted reevaluation remains narrower than full evaluation;
- benchmark batching honors concurrency/budget bounds;
- repeated renders do not trigger model calls;
- project navigation does not trigger provider calls;
- source retrieval is bounded;
- model call count is visible in run metadata.

Add practical size limits where the product spec already permits them.

Do not invent arbitrary scientific limits.

EXPORT / IMPORT HARDENING
